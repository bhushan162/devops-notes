# Linux Users, Groups & Permissions

---

## 🧠 Core Concepts

* **Linux User Account Categories:**
  * **Superuser Account (root):** Has full administrative power over the entire system (UID 0).
  * **Regular User Accounts:** Everyday accounts for people with limited permissions restricted to their own home folder (`/home/<username>`).
  * **Service Accounts (System Users):** Accounts created for system daemons and background services (e.g., `www-data`, `nginx`, `docker`, `sshd`) without an interactive login shell, minimizing security risks.

* **How Permissions Are Assigned (2 Ways):**
  * **User-level permission:** Assigned directly to the specific user.
  * **Group-level permission:** Add the user into a group, and grant permissions to the group.

* **Understanding `/etc/passwd` Entry Format:**
  * Example entry:
    ```text
    username:x:1000:1000:Bhushan:/home/bhushan:/bin/bash
       |     |  |    |      |          |           |
       |     |  |    |      |          |           +-> Default login shell
       |     |  |    |      |          +-> User's home directory
       |     |  |    |      +-> Comment / Full name (GECOS)
       |     |  |    +-> GID (Primary Group ID)
       |     |  +-> UID (User ID)
       |     +-> 'x' means encrypted password is stored in /etc/shadow
       +-> Username
    ```
  * **UID:** User ID (root is `0`, regular users start from `1000` on most distributions).
  * **GID:** Group ID (identifies the primary group the user belongs to).

* **File Ownership & Permission Structure:**
  * Every file and directory in Linux has an **Owner (User)**, a **Group**, and **Others**.
  * Permissions are represented by 3 sets of `rwx`:
    ```text
    - rwx r-x r--  1  bhushan  devops  4096  Nov  2 10:00  build.sh
      --- --- ---     -------  ------
       |   |   |         |       |
       |   |   +-> Others (Read only)
       |   +-> Group: devops (Read + Execute)
       +-> User/Owner: bhushan (Read + Write + Execute)
    ```
  * **Permission Types & Numeric Values:**
    * `r` (Read) = **4**
    * `w` (Write) = **2**
    * `x` (Execute) = **1**
    * `---` (No permission) = **0**
  * **Common Numeric Permissions:**
    * `755` (`rwxr-xr-x`): Owner has full rights; group and others can read and execute (standard for scripts and binaries).
    * `644` (`rw-r--r--`): Owner can read and write; group and others can only read (standard for config and source files).
    * `700` (`rwx------`): Only owner has access (standard for `~/.ssh` directory).
    * `600` (`rw-------`): Only owner can read/write (standard for private SSH keys like `id_rsa`).

## 🛠️ Playbook & Commands

### 1. User & Group Management

**Add and manage users:**
```bash
# Add a new user with home directory and password prompt
sudo adduser tom

# Change / set password for a user
sudo passwd tom

# Switch to another user (loads their shell and environment)
su - tom

# Login / switch as root
su -

# Delete a user and remove their home directory
sudo deluser --remove-home tom
```

**Manage groups and memberships:**
```bash
# Add a new group
sudo groupadd devops

# Set group as user's primary group (-g)
sudo usermod -g devops tom

# Add user to a secondary/supplementary group (-aG is critical so existing groups aren't wiped!)
sudo usermod -aG devops tom

# Show all groups that current user belongs to
groups

# Show all groups that a specific user belongs to
groups tom

# Verify group details and members in /etc/group
cat /etc/group | grep devops
```

### 2. Ownership & File Permissions

**Change file permissions (`chmod`):**
```bash
# Make a shell script executable for owner
chmod u+x build.sh

# Set standard script permissions: owner full (7), group read/exec (5), others read/exec (5)
chmod 755 build.sh

# Set standard file permissions: owner read/write (6), group read (4), others read (4)
chmod 644 config.yaml

# Restrict sensitive private key file to owner only (read/write)
chmod 600 id_rsa

# Recursively change permissions for all files and directories inside a folder
chmod -R 755 /path/to/directory
```

**Change ownership (`chown` and `chgrp`):**
```bash
# Change owner of a file to tom
sudo chown tom app.py

# Change both owner and group at the same time (user:group)
sudo chown tom:devops app.py

# Recursively change owner and group for an entire directory
sudo chown -R tom:devops /opt/my_project/

# Change group ownership only
sudo chgrp devops app.py
```
