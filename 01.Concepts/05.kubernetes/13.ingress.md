#Ingress
- An Ingress acts as a smart, single Reverse Proxy and Traffic Router sitting at the front door of your cluster.

```
[ Internet Users ]
                                        │
                                        │ (HTTP Port 80 / HTTPS Port 443)
                                        ▼
                   ┌────────────────────────────────────────┐
                   │    Cloud / Physical Load Balancer      │  (Single Public IP: 198.51.100.1)
                   └────────────────────┬───────────────────┘
                                        │
                                        ▼
                   ┌────────────────────────────────────────┐
                   │          INGRESS CONTROLLER            │
                   │     (e.g., NGINX, Traefik, Envoy)      │
                   └───────┬────────────────────────┬───────┘
                           │                        │
       Path-based Routing: │                        │ Host-based Routing:
       /api/*              │                        │ dashboard.vaultastra.com
                           ▼                        ▼
                   ┌──────────────┐         ┌──────────────┐
                   │ API Service  │         │Frontend Serv.│
                   └──────┬───────┘         └──────┬───────┘
                          │                        │
                          ▼                        ▼
                    [ API Pods ]             [Frontend Pods]

```


## yaml format 
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: vast-main-ingress
  namespace: vast-dev
  annotations:
    # Tells K8s to use the NGINX Ingress controller implementation
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx   # 👈 Links to the active controller
  rules:
  # 1. Host-based routing rule
  - host: dev.vaultastra.local
    http:
      paths:
      # Route all web dashboard requests
      - path: /
        pathType: Prefix
        backend:
          service:
            name: vast-frontend-service
            port:
              number: 80

      # Route all backend API requests
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: vast-ledger-service
            port:
              number: 80

```

### 2. dev.vaultastra.local
- Because dev.vaultastra.local is a custom dummy domain and not registered on the public internet, your computer's browser won't know where to send it.

How to Test dev.vaultastra.local on Your Machine
Because dev.vaultastra.local is a custom dummy domain and not registered on the public internet, your computer's browser won't know where to send it.

To test it in your local Ubuntu/Docker lab:

Step 1: Find your Ingress IP
Bash
# Get the IP assigned to your Ingress controller or Minikube/Kind node
kubectl get ingress vast-main-ingress -n vast-dev
# Or if using Minikube:
minikube ip
Step 2: Map the domain locally in /etc/hosts
Edit your local /etc/hosts file:

Bash
sudo nano /etc/hosts
Add a line pointing your domain to the cluster IP (e.g., 192.168.49.2 or 127.0.0.1):

Plaintext
127.0.0.1  dev.vaultastra.local
Step 3: Test with curl
Now you can query your Ingress locally just like a real website:

Bash
curl -i http://dev.vaultastra.local/
Or you can test it directly without modifying /etc/hosts by explicitly sending the Host header:

Bash
curl -H "Host: dev.vaultastra.local" http://<INGRESS_OR_NODE_IP>/
