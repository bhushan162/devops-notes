# CMake

> **Status:** 🟢 Active Learning  
> **Tags:** #cmake, #cross-compilation, #build-systems

## 📝 TL;DR (1-Minute Revision)
* **What is it:** CMake is an extensible, open-source system that manages the build process in an operating system and in a compiler-independent manner.
* **Primary use:** Generate native build files (like Makefiles or Ninja) and handle cross-compilation toolchains for embedded targets without touching application source code.
* **Key command:** `cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/arm-gcc-toolchain.cmake && cmake --build build`

---

## 🧠 Core Concepts
* **The Standard Workflow:**
  * **Configure / Generate:** You run cmake. It scans your CMakeLists.txt, finds your compiler, and generates a Makefile (or Ninja file) in a separate `/build` directory.
  * **Build:** You run make or ninja (or `cmake --build`). This actually calls the GCC compiler to turn your `.c` files into an executable.
  * Mental flow: `make(tool) --> CMakeLists.txt (we write) --> Makefile/Ninja --> cmake --build`
  
* **CMakeLists.txt Standard Format:**
```cmake
# 1. VERSION: This must ALWAYS be the first command. 
# It tells CMake which features are allowed.
cmake_minimum_required(VERSION 3.20)

# 2. PROJECT: Names the project and enables languages (C and C++).
# This command automatically sets up default compiler variables behind the scenes.
project(FirmwareProject LANGUAGES C CXX)

# 3. TARGET: This defines WHAT you are actually building.
# It tells CMake: "Create an executable named 'app.elf' using the file 'main.c'"
add_executable(app.elf main.c)
```

* **Modern CMake:**
  * **Adding Multiple Source Files:** You simply list them separated by spaces inside the `add_executable` command:
    ```cmake
    add_executable(firmware.elf src/main.c src/gpio.c src/uart.c)
    ```
  * **Adding Include Directories (Header files):** CMake to attach a folder to our target using `target_include_directories()`:
    ```cmake
    # target_include_directories(TargetName Scope PathToFolder)
    target_include_directories(firmware.elf PRIVATE include/)
    ```

* **Cross-Compilation Toolchain:**
  * A toolchain file for bare-metal embedded systems requires three core variables:
    * `CMAKE_SYSTEM_NAME`: Set to Generic (tells CMake we are building for bare-metal, not Linux/Windows).
    * `CMAKE_C_COMPILER`: The exact name of our ARM C compiler (e.g., `arm-none-eabi-gcc`).
    * `CMAKE_CXX_COMPILER`: The exact name of our ARM C++ compiler (e.g., `arm-none-eabi-g++`).

* **How it fits into Edge DevOps:** 
  * Out-of-source builds keep build artifacts completely separate from source code, making CI/CD cleanup trivial. Cross-compilation toolchain files let CI pipelines target different edge/embedded hardware architectures just by swapping the toolchain file flag.

## 💡 My "Aha!" Moments & Pain Points
* **What clicked for me:** 
  * `-B build` tells CMake to put all the messy autogenerated files (like the Makefile) into a dedicated folder named `build/`. This keeps our repository clean.
  * `-DCMAKE_TOOLCHAIN_FILE=...` forces CMake to read your ARM compiler settings before it processes the `CMakeLists.txt`.
* **What sucks about it:** 
  * For bare-metal targets, CMake's compiler verification step tries to link a full executable and will fail because there is no OS runtime or linker script provided yet. You have to remember to set `CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY` in the toolchain file.

## 🛠️ Playbook & Commands
**1. Generate the build system, injecting the ARM toolchain:**
```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/arm-gcc-toolchain.cmake
```
* Breaking down this command:
  * `-S .` tells CMake the source `CMakeLists.txt` is in the current directory.
  * `-B build` tells CMake to put all messy autogenerated files (like the Makefile) into a dedicated folder named `build/`. This keeps our repository clean.
  * `-DCMAKE_TOOLCHAIN_FILE=...` forces CMake to read your ARM compiler settings before it processes the `CMakeLists.txt`.

**2. Actually compile the code using the generated files:**
```bash
cmake --build build
```

**3. Set a CMake variable:**
```cmake
set(VARIABLE_NAME "Value")
```

**4. Attach include directories to target:**
```cmake
target_include_directories(firmware.elf PRIVATE include/)
```
