## 🧠 Core Concepts
* **The Standard Workflow:**
  * Configure / Generate: You run cmake. It scans your CMakeLists.txt, finds your compiler, and generates a Makefile (or Ninja file) in a separate /build directory.
  * Build: You run make or ninja (or cmake --build). This actually calls the GCC compiler to turn your .c files into an executable.
  * make(tool) --> CMakeLists.txt (we write) --> Makefile/Ninja
  * make --build 
  
* **CMakeLists.txt:**
  * Standered format
    '''bash
    # 1. VERSION: This must ALWAYS be the first command. 
    # It tells CMake which features are allowed.
    cmake_minimum_required(VERSION 3.20)

    # 2. PROJECT: Names the project and enables languages (C and C++).
    # This command automatically sets up default compiler variables behind the scenes.
    project(FirmwareProject LANGUAGES C CXX)

    # 3. TARGET: This defines WHAT you are actually building.
    # It tells CMake: "Create an executable named 'app.elf' using the file 'main.c'"
    add_executable(app.elf main.c)
    ```

## 🧠 Modern CMake
# Adding Multiple Source Files
* You simply list them separated by spaces inside the add_executable command:
```bash

  add_executable(firmware.elf src/main.c src/gpio.c src/uart.c)

```

# Adding Include Directories (Header files)
* CMake to attach a folder to our target using the target_include_directories()
```bash
target_include_directories(TargetName Scope PathToFolder)

e.g. 
target_include_directories(firmware.elf PRIVATE include/)
```

## cross-compilation toolchaine
* A toolchain file for bare-metal embedded systems requires three core variables:
  * CMAKE_SYSTEM_NAME: Set to Generic (tells CMake we are building for bare-metal, not Linux/Windows).
  * CMAKE_C_COMPILER: The exact name of our ARM C compiler.
  * CMAKE_CXX_COMPILER: The exact name of our ARM C++ compiler.

## build it 
```bash
# Step 1: Generate the build system, injecting the ARM toolchain
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/arm-gcc-toolchain.cmake

# Step 2: Actually compile the code using the generated files
cmake --build build

```
* Breaking down Step 1:
  * -S . tells CMake the source CMakeLists.txt is in the current directory.
  * -B build tells CMake to put all the messy autogenerated files (like the Makefile) into a dedicated folder named build/. This keeps our repository clean.
  * -DCMAKE_TOOLCHAIN_FILE=... forces CMake to read your ARM compiler settings before it processes the CMakeLists.txt.
